# 投稿流程规范

> 适用范围：创建投稿包、多期刊版本管理、同一期刊修订、被拒重投
> 前置条件：`paper.md` 已完成；安装了审查技能时，其审查流程已闭环
>
> 单仓库形态：无 submit/ 分支，投稿包直接在 main 上提交，
> 投稿动作 = 打 `<项目名>-v<主>.<次>-<目标>-submitted` 标签（全局命名空间带项目前缀）。

---

## 〇、需要用户决策的时刻（AI 主动汇报）

本流程**只有四类事需要停下来问用户**，其余 AI 直接做完汇报结果（导出失败、格式不达标这类可自行修复的，改完汇报即可）。

| 时机 | 要用户决定什么 | AI 先备好 |
|:-----|:---------------|:----------|
| 用户说"准备投稿" | 前置不满足时，是否仍要进入投稿流程 | 三项前置的实测结果：审查技能是否闭环（`review/sessions/` 最新一轮；未装技能则显示未启用）、工作区是否干净、字数是否在目标期刊范围内 |
| 生成投稿包过程中 | ① 论文内容的实质性修改（删段／补段／改结论）② 声明项的具体内容（资助、CRediT 等只有作者知道）③ 投稿信内容 | 可对比的方案或骨架，而不是问"你想怎么写" |
| **打投稿标签前** | 是否打 tag；确认目标期刊 | 该期刊的引用风格／字数限制／Abstract 结构／声明项要求（**自行查阅官方投稿指南，不依赖预设**，结论写入 `write/export/<目标>/submission_requirements.md`）。标签命名与版本号规则见 `AGENTS.md §四 提交规范`（唯一权威，本文不重复） |
| 收到审稿意见／被拒后 | 修订策略（是否需重跑数据）；被拒后是否修订再投、投哪家 | 意见分类（内容／数据／格式）+ 归纳摘要；该刊标签指向的投稿包是否完整可用；新旧目标的格式差异清单 |

## 一、多期刊版本管理（标签策略）

`main` 分支上的 `paper.md` 始终保持**期刊无关的规范版本**。每个期刊的适配版作为投稿包留在 `main` 上，用标签标记投稿动作：

```
main                                      ← 唯一分支：期刊无关的规范版 + 各期刊投稿包并存
  └── write/paper.md                      ← 源稿（唯一内容源）
  └── write/export/<目标>/                ← 该目标的投稿包（submission_manuscript.md + figures/ + docx）
  └── tag: <项目名>-v<主版本>.<次版本>-<目标>-<动作> ← 投稿动作标记
```

**版本架构**：
- `paper.md`：主版本（唯一内容源）。投稿适配从它复制。
- `submission_manuscript.md`：投稿包的格式版（从 `paper.md` 复制 + 期刊格式适配），与源稿同仓并存。

**两条常驻规则**：

1. **`write/export/` 下任何时候只保留当前目标一个目录**：各目标目录没有编号，多份并存时投稿期检查分不清哪一份是「当前投稿包」（检查按 `**/submission_manuscript.md` 全树取件），故设计上只留一份。被拒改投时：**先打旧目标的 `-submitted` 标签、再删目录**——内容在 git 里不会丢，但删完就没有指向它的名字了，回溯只能靠标签。**`git rm -r` 只移除被跟踪的文件**——目录里若有未跟踪的 `.DS_Store` 之类，空目录会残留，需再 `rm -r` 一次确认删净。
2. **状态由 `detect_status` 判定，不手工推断**：已打 tag 且包无改动 → "已投稿至该期刊，审稿中（Under Review）"；包有更新或出现新目标目录 → "待打新 tag 后提交"。

## 二、投稿包文件组织与易错点

**前置阅读（导出前必读）**：创建投稿包前，必须先完整执行 md-to-word-academic 技能 §一 的导出流程（含第 0 步收集需求）。

在 `main` 上执行。文件组织与易错点见本节两表：

**投稿包易错点速查表**（除标注**无 check** 的两行外，均已由 check 或导出流水线拦下，撞到时按提示修即可；写法细节一律指向 `md-to-word-academic` 技能，本文不复述）：

| 易错点 | 谁拦 | 对策 |
|:-------|:-----|:-----|
| 投稿包就绪但没打标签 | `check_submission_tag`（投稿期 error，按目标核对） | 投稿动作 = 打标签，打完即消解 |
| `csl:` 指向不存在的文件 | `check_csl_path`（与导出预检同口径） | 写绝对路径，或写**相对稿件所在目录**的路径——渲染器只认这两种，检查同口径 |
| 摘要／关键词没写成 `%% 样式行` | `check_header_wrap`（投稿期） | `%% Abstract Title 摘要` + `%% Abstract 正文` + `%% Keywords 关键词1；关键词2`，见 `md-to-word --guide` |
| 表格题注／表注没写成 `%% 样式行` | **无 check**——判据立不住（正文句也以「表 N」起头，见 `lib_common._table_caption` 的说明） | 表题在表格上方写 `%% Table Caption 表 1：…`、表注在下方写 `%% Table Note 注：…`；漏写会以正文样式出现（与正文同大），要照 §五 渲染抽查核对。**图片题注同理**：图片行只放路径与宽度，题注另起一行 `%% Image Caption 图 1：…` |
| 块级标记（公式／短代码／表格／图片行）与正文黏连 | `check_block_separation`（投稿期 error） | 按要求留空行，哪一侧要空行见 `md-to-word --guide` |
| **版式走形**（列宽被压成逐字母断行、版心溢出、跨页断行） | **无 check**——字符串层看不到版式 | 投稿前必跑 `--pdf` 渲染 + 4 点拓扑抽查（§五），**结论写进 `generation_log.md`**（四节写法见 §五） |

### 投稿包文件组织（`write/export/<目标>/`）

主流国际期刊（如 Emerald、Springer、Elsevier 等）多用双盲评审，并要求材料分立提交。**按目标期刊指南决定取"单文件内嵌模式"还是"双盲分立模式"**，文件统一收拢在本目录：

| 产出物 | 源文件 → 导出件 | 作用与处理要求 |
|:-------|:----------------|:---------------|
| **盲审正文（Blind Manuscript）** | `submission_manuscript.md` → `[目标]_submission.docx` | 仅保留正文、参考文献与图表（或占位符）。**严禁出现作者姓名、单位、致谢、资助项目编号**；正文自引须用中性第三人称 |
| **独立标题页（Title Page）** | `title_page.md` → `Title_Page.docx`（可选） | 论文标题、全部作者信息、通讯作者、机构、ORCID、致谢、**声明项**（Funding／Competing interests／Ethics／Consent／Data／Code／Authors' contribution）。**声明项按目标方要求决定放这里还是并入正文**——Springer 等要求集中于独立题页，Elsevier 等可置于正文后置小节；放题页时主稿内不得留声明节 |
| **独立表格文件（Tables）** | `tables.md` → `Tables.docx`（可选） | 强制表格分立上传的期刊（如 Emerald APJML）：正文表格抽至 `tables.md`，正文保留 `[Insert Table N about here]` |
| **独立图片包** | `figures/`（可选） | 期刊要求图与正文分开上传时使用 |
| **期刊要求与模板规范** | `submission_requirements.md`、`[目标]_requirements.txt` | 官方投稿规范存档 + 模板生成规范（导出时据此实时生成临时 Word 模板，二进制模板中间件不进版本库） |
| **留痕文件** | `generation_log.md` | **四节必写**（见 §五）：它是"该看的看过、该判的判过"的唯一痕迹。`check` 验存在性与四节齐全，缺文件报 error、缺小节给提示 |

## 三、同一期刊审稿意见修订（Revise & Resubmit）

**场景**：期刊返回"修改后重投"决定（非拒稿），要求修改后重新提交到**同一期刊**。

**与 §四（被拒后重投新期刊）的区别**：
- 已有 `<项目名>-v<主版本>.<次版本>-<目标>-submitted` 标签，期刊格式/CSL/模板已适配好，可直接复用
- 内容修改在 `main` 上完成（单仓库无分支，天然单内容源）

**目录契约**（`check` 的 `revision_dirs` 按此核对；只核「件在不在、槽位填没填、轮次登记自不自洽」，**不判回复质量**）：

```
review/revisions/R<轮次>/
├── revision.json          ← 轮次 / 目标期刊 / 投稿版 tag 与 commit（增量复审的起点）
├── response_letter.md     ← 逐条回复，每条意见一个 `### ` 小节
└── journal_letter.<扩展名> ← 期刊来信原件：决定信 PDF、邮件导出（eml/msg）或 docx/txt/md 摘录
```

> **来信文件名固定**：主干名就是 `journal_letter`，扩展名随原件形态（`journal_letter.pdf` /
> `.eml` / `.docx` …）。期刊系统导出的名字五花八门，检查不去猜关键词——放进来时**重命名一次**，
> 之后每轮都这么放，判据就是一次精确比较。

### 1. 准备修订目录

```bash
cd <项目> && python3 ../papergate/papergate.py revision new R1
```

生成上面两个文件的骨架：`revision.json` 从最新的 `-submitted` 标签取目标期刊与投稿版 commit，`response_letter.md` 的待填位置一律写成 `<待填>` 这类尖括号槽位。**只补缺失文件，不覆盖已有内容**——重跑是安全的。随后把期刊来信原件重命名为 `journal_letter.pdf`（或对应扩展名）放进该目录。

> 槽位还在 = 没写完。`status` 与 `check` 都按这条认：空骨架不会被报成「回复信已写」，落盘当天就能看出这一轮还没动。

### 2. 分析审稿意见并分类

AI 主动归纳审稿意见，分类并建议策略：

| 修改类型 | 示例 | 建议策略 |
|:---------|:-----|:---------|
| 内容修改 | 补充 limitations、调整表述、修正笔误 | 直接改 paper.md + 重跑相关审计 |
| 数据重分析 | reviewer 要求新的 robustness check、补充统计 | 改 scripts → 重跑 → 更新 results → 改 paper.md |
| 格式调整 | 表格格式、参考文献格式 | 在投稿包中调整 |
| 大段新增/重写 | 新增一节、重构方法描述 | 改 paper.md + 重跑相关审计 |

### 3. 修改源稿 + 增量复审（只重审受影响的模块）

```bash
# 3a. 按审稿意见修改 write/paper.md

# 3b. 复核改动范围：起点是投稿版 commit（revision.json 的 base_commit）
git diff --stat <base_commit>..HEAD -- write/paper.md results/ scripts/
```

**复审范围由意见类型决定，不整轮重跑**——修订期的复审对象是「相对投稿版改了什么」，
不是「整篇再审一遍」。第 2 步的分类直接决定重跑哪几个审计模块：

| 意见类型 | 受影响模块 | 范围怎么定 |
|:---------|:-----------|:-----------|
| 内容修改（补 limitations、改表述、修笔误） | 叙事；改动了引文支撑句再加引文 | 按 diff 逐条对：改到哪些句子，哪些引用挂在那些句子上 |
| 数据重分析（新 robustness、补统计） | 数值（必）+ 叙事（新数字进正文的说法） | 先重跑管线 → 数值审计按新产物重做受影响条目 |
| 引用增删 / 换文献 | 引文 | `audit-diff --since <base_commit>` 直接列出支撑句变动的 citekey，只重审这些 |
| 格式调整（表格 / 参考文献样式） | 格式 | 按 §五 重新导出后核对，不必进四模块 |
| 大段新增 / 重写（新增一节、重构方法） | 叙事 + 引文（新引用）+ 数值（含新数字时） | 新增节按全新内容审，存量部分按 diff |

装了审查技能时，引文模块的增量范围由工具算：

```bash
cd <项目> && python3 ../papergate/papergate.py audit-diff --since <base_commit>
```

审查侧怎么登记这一轮、`round.json` 填什么、哪些模块可以沿用上一轮结论，见
`skills/review-audit/standards/review.md`「修订期：针对审稿意见的增量复审」。

```bash
git add write/paper.md
git commit -m "[<应用标识>] 写作/修正：第R<轮次>轮审稿意见修改"
```

### 4. 重新导出投稿包

**这一轮是重跑 §五**：覆盖投稿稿（`cp write/paper.md write/export/<目标>/submission_manuscript.md`）后，按 §五 执行要点 1–4 走一遍（模板/CSL/图表处理沿用该目标已有的配置，无需重选），并重写 `generation_log.md` 的适配项与抽查结论两节。

```bash
git add write/export/<目标>/
git commit -m "[<应用标识>] 投稿/修正：第R<轮次>轮投稿包重新导出"
```

### 5. 写回复信

填充 `review/revisions/R<轮次>/response_letter.md`，逐条回复：
- **每条意见一个 `### ` 小节**（`revision new` 的骨架已按此排好，`check` 按小节数核「有没有逐条回复」）
- 审稿意见原文 + 你的回复 + 对应修改位置
- 确保每条意见都有回应，不跳过
- 把骨架里的 `<…>` 占位全部替换掉——占位还在 = 这一轮还没写完

回完跑一次 `python3 ../papergate/papergate.py check`：`revision_dirs` 会报出未填占位、
缺期刊来信、轮次登记与目录名不一致；`status` 的子阶段据此决定是「待写回复信」还是
「回复信已写，待修订 paper」。**它不判回复写得好不好**，那是审稿人与人的活。

### 6. 打修订标签 + 归档

```bash
git add review/revisions/R<轮次>/
git commit -m "[<应用标识>] 审查/新增：第R<轮次>轮审稿意见回复"
git tag <项目名>-v<主版本>.<次版本>-<目标>-revised-R<轮次>
```

标签命名与版本号规则见 `AGENTS.md §四 提交规范`（唯一权威，`check_git_tag_naming` 自动校验）。
标签里的 `R<轮次>` 应与 `revision.json` 的 `round`、目录名三者同号：`revision_dirs` 核对登记与目录名，
标签本身只由 `git_tag_naming` 查格式（`-revised-R<n>` 的形状），号对不对得上一眼确认。

### 7. 上传

按 `generation_log.md` 的「产出清单 + 投稿系统操作项」节照单上传（该节记录了每个文件对应的系统类别）；修订轮另需上传回复信。

---

## 四、被拒后重投（新期刊）

1. 修复审稿人提出的问题（如有）或保持原样（源稿在 main 上，无需切换）
2. 修订后按所安装审查技能的协议重跑受影响模块
3. 按 §二 适配新期刊要求（新建 `write/export/<新目标>/`），旧目标目录按 §一 常驻规则 1 清理
4. `git tag <项目名>-v1.0-<新目标>-submitted`（**新目标从头起算**——版本号按期刊独立，换刊重新从 `v1.0` 开始）

## 五、投稿包生成步骤（当前对话执行）

**产出物与命名口径见 §二 的文件组织表**。步骤：

**`generation_log.md` 的四节**（让该看的看得出看过、该判的判过）：

| 节 | 写什么 | 为什么必须写 |
|:---|:-------|:-------------|
| 适配项 | 目标期刊、源稿 commit、模板/CSL、逐项适配与改动理由 | 下轮改投或修订时，唯一能回答"这份包跟源稿差在哪、为什么差"的地方 |
| **4 点渲染抽查结论** | 首页 / 最宽复杂表 / 公式 / 参考文献四处，各一句结论；**最宽表须写明列宽与换行是否正常** | §二 速查表末行要求投稿前必跑渲染抽查，但渲染检查不出"没跑"——写结论是这一步唯一的验收痕迹 |
| **自检警告逐条结论** | 本轮 `check --stage submission` 每条警告一条结论：`设计如此（原因）` / `待处理（计划）` | 投稿期必然带几条"关键但不好检查"的上位提醒（声明件、投稿稿引文差异等），逐轮重判一遍是纯浪费；写下结论后，下轮只看新出现的 |
| 产出清单 + 投稿系统操作项 | 上传哪些文件、各选什么类别、还缺哪些用户输入（作者信息等） | 投稿动作在系统侧完成，包内必须能独立回答"接下来谁做什么" |

**执行要点**：

1. 先检查 `write/export/<目标>/submission_requirements.md` 是否存在。若存在则以该文件为期刊要求主要来源；若不存在则联网查阅目标期刊投稿指南，整理后写入该文件。格式标准以 `check --stage submission` 实际执行的规则为准；导出技术流程按 md-to-word-academic 技能 §一 完整执行（本文不重复）
2. 复制 `paper.md` → `submission_manuscript.md`，逐项适配：
   - YAML：`csl:` 改为目标期刊 CSL 路径，`bibliography:` 路径调整为相对投稿包的路径
   - 盲审脱敏：若为双盲评审，移除 YAML 及正文中的作者名、单位、致谢、资助信息；将这些信息统一归入独立 `title_page.md`
   - 图表拆分（如期刊要求）：见 §二 文件组织表「独立表格文件」「独立图片包」两行
   - 图片：以该期刊投稿指南为准，多数接受 docx 内嵌图片无需替换，少数传统排版流程要求 `![](../results/figures/<描述名>.png)` → `[Insert Figure X about here]`（图文件名用纯描述名，禁 `fig<N>_` 前缀，命名规则由写作期检查执行）
   - 文内引用连接词：作者-年份风格切换时 grep 检查 `&` / `and`（双风格对照由写作期检查执行）；Vancouver 不涉及
   - Abstract 结构：按期刊要求调整子标题
   - 声明项：按目标方要求补齐，并决定归属（独立题页 / 正文后置小节）——见 §二 文件组织表「独立标题页」行
3. 按技能 §一 导出 docx：
   - 导出主正文：`python3 ../papergate/papergate.py export write/export/<目标>/submission_manuscript.md -o 输出.docx`
   - 若有独立表格：`python3 ../papergate/papergate.py export write/export/<目标>/tables.md -o write/export/<目标>/Tables.docx`
