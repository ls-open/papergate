# 引用标准（Citation Standards）

> 适用范围：写作引用、投稿前引文审计
> 审查执行流程由审查技能提供（未安装技能时审查能力显示「未启用」）。
> 笔记规范与多模态提取由文献技能提供。

**Severity 定义**：学术严重性轴的等级语义以 `system.md §2.4` 为权威依据；修复权限由审查技能定义。本表仅列**审查领域专属示例**：

| 等级 | 引文领域示例 |
|:-----|:------|
| **Critical** | 核实发现某篇支撑性文献已撤稿 |
| **Major** | 来源等级不足却用在核心论点、语境匹配严重偏差 |
| **Minor** | 联合引用中某条不必要、间距格式问题 |
| **Safe** | 年份标错（不影响引用准确性） |

## 〇、正文引用语法

### 0.1 两根正交的轴（勿混为一谈）

引用在成稿里的**外观**由两件**互相独立**的事决定：

- **轴一 · 键怎么写**：裸键 `@a` 还是方括号 `[@a]`
- **轴二 · 用哪套 CSL**：**数字制**（顺序编码制）还是**作者-年份制**

**只有作者-年份制下，轴一才有区别。** 数字制下两种写法渲染**完全相同**——都只剩编号，作者名根本不出现。

| 写法 | 数字制（`chinese-gb7714-2015-numeric.csl`） | 作者-年份制（`chinese-gb7714-2015-author-date.csl` / `apa.csl`） |
|:-----|:-----|:-----|
| `@a`（裸键） | `^[1]` | 作者 (年份)　← **作者在正文里** |
| `[@a]`（方括号） | `^[1]` | (作者, 年份)　← **作者在括号里** |
| `@a @b`（裸键多条） | `^[1] ^[2]` | 作者A (年) 作者B (年) |
| `[@a; @b]`（方括号多条） | `^[1,2]` | (作者A, 年; 作者B, 年) |
| `[-@a]`（抑制作者） | `^[1]` | (年份) |

> 表为实测结果（Pandoc + citeproc；三个 CSL 取自导出引擎 `md-to-word` 的内置库，与论文侧 `csl:` 用的是同一批文件）。
> **写法与条数是两回事**：`@a @b` 是裸键多条、`[@a]` 是方括号单条，都合法。

**据此的约定**：

- 中文**学位论文 / 中文学术期刊**用**数字制**（GB/T 7714 顺序编码制，模板参考文献表作 `[1][2][3]`）。
  此时选哪种写法只影响**源文件可读性**，不影响成稿外观——**统一用裸键 `@a`**。
- 英文社科期刊（APA / Harvard 等）用**作者-年份制**。此时**必须按语义选**：作者要出现在句子中就用裸键，
  要缩进括号里就用方括号。选错会直接改变成稿语义。

### 0.2 数字制下如何写出「作者（年份）」

数字制下 CSL **不会**输出作者名。若行文需要「某某（年份）提出……」这类**叙述式引导**（中文管理学学位论文的
常见写法，用于交代某条结论出自谁，读者不必翻参考文献表），**只能在正文里手写**，句末照常挂编号：

```markdown
Fiske 等（2007）提出温暖与能力是用户评价智能系统的两个核心维度 @fiske_universal_2007。
```

渲染为 → `Fiske 等（2007）提出温暖与能力是用户评价智能系统的两个核心维度^[1]。`

> **不要**为了得到这种外观而把 CSL 换成作者-年份制——那会连**参考文献表**一起改成著者-出版年格式，
> 与学位论文模板的 `[1][2][3]` 顺序编码制冲突。手写引导语 + 数字制 CSL 是唯一不冲突的做法。
> 手写时必须写对**作者姓氏与年份**（从 `.bib` 取），写错即硬伤。

## 一、文献准入分级

引用时根据来源类型区分使用方式，禁止无差别引用：

| 等级 | 来源类型（确定性分类） | 使用方式 |
|:-----|:---------|:---------|:-----|
| **A 级（核心）** | 期刊论文（`@article`）、学术专著/专著章节（`@book` / `@incollection`） | 可用于支撑核心论点、理论框架、关键对比 |
| **B 级（支撑）** | 会议论文（`@inproceedings`）、权威机构技术报告（`@techreport`） | 可用于支撑辅助论点、方法论背景、宏观趋势 |
| **C 级（辅助）** | 预印本（arXiv/SSRN）、学位论文、未出版手稿（`@misc` / `@unpublished`） | 仅可用于方法细节边缘支撑；**不能**用于核心理论或因果推断 |
| **D 级（不引用）** | 博客、新闻、维基百科、商业报告（无公开方法论） | **禁止引用**；仅可在引言背景段作为信息源提及 |

> **分级依据（确定性优先）**：A/B/C 仅由**来源类型**（bib entry type）静态判定，由审查技能的前置步骤自动写入 `source_level_defaults.json`（confidence="high"）；**D 级（博客/新闻/维基等不引用类型）属人为不引用范畴，无自动判定**。等级反映的是"这是什么类型的文献"，**不反映质量**。
>
> **质量评估在体系外**：期刊/会议的质量（如 Q1-Q4、分区、声誉）属不确定性维度，框架不判定、不检查。需要时由用户自行判断，或让 AI 联网代为审查（如对某期刊是否值得引用、某会议级别如何），此为框架外行为，不属于本体系流程。

**B 级约束**：技术报告/行业报告必须有公开方法论和原始数据，纯商业报告归入 D 级。

#### 各章节 A 级占比要求（审计人工判定）

> 本检查衡量**类型构成**（综述章节应以期刊/专著为主，而非预印本/学位论文），属提醒性质，非质量闸门。若引文以 C 级为主，即使满足占比阈值，质量好坏仍由用户在框架外判断。

| 章节 | 要求 |
|:-----|:-----|
| §2 Literature Review | A 级 ≥ 85%，不得出现 C 级 |
| §5 Discussion | A 级 ≥ 70%，每个关键对比至少 1 篇 A 级支撑 |
| §1 Introduction / §6 Conclusion | A 级 ≥ 60% |
| §3 Methods / §4 Results | C 级可接受但不超过该节引用的 20%（主要为方法引用） |

## 二、引用密度基准

### 2.1 键数基准（check.py 自动校验）

各章节最小引用键数采用"绝对值与百分比取较低者"的柔性规则，由 `check_citation_density` 自动校验：

| 章节 | 绝对值下限 | 或百分比下限 |
|:-----|:---------:|:----------:|
| §1 Introduction | ≥ 12 | ≥ 全文总引用的 15% |
| §2 Literature Review | ≥ 25 | ≥ 全文总引用的 30% |
| §3 Data & Methods | ≥ 15 | ≥ 全文总引用的 15% |
| §4 Results | 不限 | — |
| §5 Discussion | ≥ 8 | ≥ 全文总引用的 15% |

> **章节范围**：密度基准只校验 §1–§5。§6 Conclusion 不单独设基准——5 章合并结构
> （§5 Discussion 含 Conclusion）与 6 章独立结构均适用；合并进 §5 时按 §5 基准校验，
> 独立 §6 也不额外要求，避免「未检测到 §6 章节」误报。

> **自动校验说明**：上表阈值由 `check_citation_density` 自动校验。**投稿期 severity=error（硬门禁）**，写作期/审查期为 warning（提示，不阻塞——写作/审查阶段引用可能仍在补充，属过程性状态）。任一章节未达「绝对值下限」**且**未达「百分比下限」即报错/提示。阈值集中在 `check_shared.py::CITATION_DENSITY_BASELINE` 常量实现（`check_citation.py::check_citation_density` 消费该常量）。**调整阈值改项目配置、不改常量也不改本表**——本表只说明含义，改法与学位论文档的差异见 §六。

### 2.2 段级密度（审计人工判定，定性规则）

引用密度由审计执行者在引文审计中**定性**核对（不再逐表统计百分比，避免精确到小数却无法执行的负担）：

- **每节至少半数段落有引用**（纯数据/结果段除外，解释性段落必须有引用支撑）
- **每段引用数 1-5 条为宜**，联合引用 ≥3 时确认每条都必要
- **零引用段按节提醒**：Discussion / Literature Review 中连续零引用段要重点标注

**硬红线（不可柔性）**：NEI 键数=0、撤稿引用=0。

## 三、引用分布指南

### 3.1 引用倾向分布

论文各章节的引用倾向分布遵循编辑经验法则（非实证文献计量标准，审计时定性判断）：

- **引言**：背景定位、研究缺口定义（~15-20%）
- **文献综述**：系统性理论回顾、多角度对比（~25-30%）
- **方法与数据**：方法选择理由、数据来源说明（~10-15%）
- **结果**：纯结果少引，仅解释性内容需引（≤ 5-10%）
- **讨论**：核心对比、与文献对话（~25-30%）
- **结论**：适度回顾性引用（~5-10%）

> **Rules of thumb**：对于无独立 Literature Review 章节的 IMRaD 论文，Introduction + Discussion 合计应占全文引用的 50-60%。有独立 §2 Literature Review 时此规则不直接适用。某节引用占比明显偏离上述范围时，标记为 🟡 建议重审。

### 3.2 时效性标准

| 引用类型 | 时效要求 | 说明 |
|:---------|:---------|:------|
| 理论/方法经典 | 不限年份 | 如 Rogers 2003、Blei 2003 |
| 实证研究 | 近 5 年内 ≥ 70% | 实证领域引用老文献需注明经典性 |
| 方法基准 | 近 8 年内 ≥ 80% | 技术方法更新快 |
| 行业/政策报告 | 近 3 年内 | 过时报告不应作为依据 |

## 四、语境匹配检查（审计环节）

每次引用必须在审计时做三步验证：

```
Step 1：citekey → 是否有笔记/摘要（可访问性）
Step 2：笔记/摘要 → 是否能支撑论文中的上下文（匹配性）
Step 3：论文上下文 → 引用是否在所属章节合理使用（必要性）
```

#### 证据边界原则

引用声称只能落在证据源（笔记或摘要）的覆盖范围内，不得超出：

- **full（有笔记）**：声称受笔记全文覆盖，可引用任意原文支撑的内容。
- **partial（仅有摘要）**：声称只能被摘要直接覆盖。若正文需要引用摘要之外的内容（如通过他文转引或网络检索得知的细节）：
  1. 优先提醒用户获取 PDF 转 full_text 笔记；
  2. 用户无法提供 PDF 时，压缩声称回摘要范围内（Partial）或删除该引用。
- **concept_note（无 PDF 无摘要，老文献/书籍）**：基于公开权威元数据生成，声称受该笔记覆盖，同样不得超出。

> 写作期批量采集文献时可先用摘要/元数据落地；**最终审计时所有引用必须回到证据边界内**——超出摘要范围的声称需有笔记支撑，否则压缩或移除。

#### 判定标准

| 判定 | 含义 | 处理 |
|:-----|:-----|:-----|
| **Yes** | 笔记/摘要完全支撑上下文 | 保留 |
| **Partial** | 笔记/摘要部分支撑，有扩展或推断 | 标注"Partial"，修改措辞缩小声称范围；若缺口来自"只有摘要"（声称需要摘要之外的细节），先提醒用户找 PDF 转笔记，找不到则压缩声称回摘要范围内 |
| **NEI（不能支撑上下文）** | 笔记/摘要不能支撑上下文 | **必须修**：补充笔记、替换措辞或移除引用 |

#### 强制规则

投稿前审计结果硬红线：**NEI=0、撤稿=0**（不可柔性，见 §二）；**Partial≤15% 为投稿前阈值**（超限时压缩声称修复——修改措辞缩小声称范围即可，非不可柔性，见 §六 指标表）。

#### 引用择优：只判「被支配」，不判「最优」

> 上面三步验证回答的是「**这里的引用对不对**」。还有一问是「**有没有更合适的**」——
> 这一问**没有确定性判据**（最优是价值判断，用启发式打分即 README §三 所说的脆弱推断）。
> 但可以降级处理：**不判最优，只判被支配。**

**判据**：若现引文献在某条**已声明的属性**上劣于库内另一篇能支撑**同一声称**的文献，则报一条落差提示。
「A 比 B 好」不可判；「A 在属性 X 上明确不如 B」可判。

**可比较属性**（只用框架内已有确定性来源，**刻意排除**期刊分区/影响因子/声誉——已声明不判）：

| 属性 | 取值 | 来源 |
|:-----|:-----|:-----|
| 证据级别 | `full`（有笔记）/ `partial`（仅摘要）/ `none` | `evidence_inventory.json` |
| 来源等级 | A / B / C | `source_level_defaults.json` |
| 发表年份 | 年份 | bib |
| 研究对象贴近度 | 同场景 / 跨场景 | 读笔记（半确定，有证据可复核） |

**四条落差规则**（都写成"落差"，不写成"打分"）：

| ID | 落差类型 | 触发条件 |
|:---|:---------|:---------|
| **R1** | 证据落差 | 现引为 `partial`，库内有 `full` 的备选可支撑同一声称 |
| **R2** | 等级落差 | 现引为 B/C 级，库内有 A 级备选可支撑同一声称 |
| **R3** | **归属落差** | 正文把某准则/理论/方法的提出权归给某文献，而该文献并非其出处——**价值最高，因为它不需要"找更好的"，只需核对归属是否成立** |
| **R4** | 场景落差 | 现引研究对象与论文场景不同（如跨学科/跨领域借用），库内有同场景备选 |

**候选从哪来**：以该处正文的声称作 query，在**本库**检索（候选**不出库**，外部"还有没有更好的"无确定性来源，不做）：

```bash
python3 ../papergate/papergate.py note-sec --search "<该处声称的核心关键词>"
```

**执行范围**：定点跑，不每处跑。必跑——H1–H4 推导、理论锚点（§2.2）、方法学援引；跳过——背景铺陈的并列引用。
范围规则与本文件 §二/§三 同源，勿各定一套。

**性质**：**弱提醒，不改正文**，逐条附具体落差证据（"现引仅有摘要 / 备选有全文笔记 xxx.md"），交作者定夺。
它给的是**事实**（A 是 partial、B 是 full），不是**意见**（我觉得 B 更好）——故非脆弱推断。

## 五、撤回一条引用（删除流程）

审计发现某条引用不该保留（NEI、语境不匹配、来源等级不足、联合引用中多余）时，按以下流程安全撤回，保持三方闭环一致：

1. **从 `write/paper.md` 删除 `@citekey`**（连同所在句子的引用括号），必要时调整句子使其完整
2. **`papergate.py check --stage citation` 验证闭环**：
   - 正文不再引用 → 触发 `notes_bib_closure` 等检查的**反向**提醒（笔记/PDF 仍在库中但正文未用 → 判断是"暂未引用"还是"应清理"）
   - 若确认该文献彻底不用 → 在 Zotero 线上库删除条目（用文献技能或桌面端），再按技能说明同步 `.bib`
3. **决定笔记/PDF 去留**：
   - 论文未来可能再用 → 保留 `references/notes/` 与 `references/pdfs/`
   - 确认永不使用 → 删除笔记与 PDF 文件
4. **同步项目 `write/research-plan.md` §5 关键决策记录**：一行记录"撤回 X 及原因"，便于后续追溯

> **原则**：撤引用和加引用一样，都要保持 paper / bib / notes / pdfs 四者闭环。删正文引用后若检查器提醒"笔记未使用"，先判断是暂未引用还是永久弃用，不要机械删除。

## 六、审计指标

> **等级数据来源**：A/B/C/D 等级由审查技能的前置步骤确定性静态判定（依据见 §一 分级依据，写入 `source_level_defaults.json`）；NEI 数 / Partial 比例由审查技能统计，以下指标均为提醒/硬红线：

| 检查项 | 方法 | 阈值 |
|:-------|:-----|:-----|
| 总引用数 | 统计全文唯一 citekey 数 | **下限**：期刊 30 条 / 学位 50 篇（培养单位规定）——学位论文的文献量要求远高于期刊论文，切勿套用期刊基准<br>**上限**：**默认不设**（各刊自定）；目标刊有上限时在项目 `[citation] total_max` 设，**投稿期对投稿副本判** |
| A 级覆盖率 | A 级键 / 总键 | ≥ 60% |
| A+B 覆盖率 | (A+B) 级键 / 总键 | ≥ 85% |
| NEI 数 | 统计 NEI 判定键 | **必须为 0** |
| Partial 比例 | Partial 键 / 总键 | ≤ 15% |
| 引用倾向偏离 | 单节引用占比 vs 参考范围 | 任一偏离 > 2x → 🟡 建议修 |
| 实证引用时效 | 近 5 年引用 / 实证引用总数 | **期刊论文**：≥ 40%（实证 4 个真实项目落在 40%–60%——取 70% 会让正常论文恒报不达标）<br>**学位论文**：按培养单位规定（常见"近五年 ≥总数 1/3，并应有近两年"） |

> **文体差异由配置驱动（勿再各处硬编码）**：本表所列阈值随文体而变，取值见
> `papergate/tools/lib_config.py` 的 **`DOC_KIND_PROFILES`**，由项目 `.papergate_config` 的
> **`[document] kind`**（`journal` | `dissertation`，缺省 `journal`）选择：
>
> | | journal（期刊论文） | dissertation（学位论文） |
> |:--|:--|:--|
> | 总引用数下限 | 30 条 | ≥50 篇（培养单位规定） |
> | 总引用数上限 | **不设**（各刊自定，需要时按刊配置） | 不设——引用多不是缺点 |
> | 实证引用时效 | ≥40%（实证值） | 近五年 ≥ 总数 1/3，并应有近两年 |
> | 外文文献 | — | ≥20 篇 |
> | 各章密度基准 | IMRaD 语义映射 | 按论文**自身章号**语义 |
>
> **判定口径一致，差异只在数值**：体量四轴对**所有文体**统一判定（写作期 warning /
> 投稿期 error），不按文体在代码里分叉出两套行为——分叉会让同一份规则要维护两种实现。
> 阈值取文体档位默认；只有总量**上限**可在 `.papergate_config [citation] total_max`
> 覆盖——上限是目标刊属性，各刊差异大，其余三项是文体基准。
> **改阈值改配置，不改本表**——本表只说明含义。
>
> **上限的特殊语义**：它是**目标刊**属性，而源稿保持期刊无关、按目标裁剪（如 65→60）
> 正是正常操作——故上限**只对投稿副本判**（无副本则不判该轴），绝不会拿目标刊的上限去卡源稿。

## 七、文献笔记类型与证据等级

> **单一权威**：笔记类型、证据可靠性、字段定义、生成流程、frontmatter 职责等规范以文献技能提供的笔记规范为唯一权威。本节仅保留**证据等级判定**（full/partial/none），避免同信息多处维护导致漂移。

**证据等级判定**（`check_evidence_level`，见 `check_citation.py`）：
- `full`：有笔记 + `note_type` 合法 + `generated_by` 合法
- `partial`：无笔记 + bib 有 abstract
- `none`：无笔记 + bib 无 abstract

> 提取精修执行协议由文献技能提供。

## 八、文献库同步规范

`.bib` 是 Zotero 的编译产物，由 Git 跟踪（`check_bib_git_tracked` 校验跟踪状态）。规范只剩一条主路径与一条兜底：

1. **默认路径：改 Zotero，再同步**。文献的采集、增删、类型变更都在 Zotero 线上库操作——**新建条目由用户完成**（桌面端 / 浏览器技能），AI 可改已有条目（删除先确认）；同步命令由文献技能提供，同步后用 Git 入库。
2. **兜底：本地误改有 Git 保底**。手改 `.bib` 会与线上库脱节、下次 `pull` 即被覆盖（白做），所以默认不要手改；但真改了也不构成事故——提交入库即可，要回退随时 `git checkout -- write/references.bib`。

## 九、文献库字段完整性标准

`.bib` 是受版本控制保护的编译产物（§八），字段必须满足 BibTeX 类型规范。必填字段、通用规则
（`doi`/`url` 字段存在性——book/techreport/misc 豁免，可定位性需人工确认；keywords ≤ 12、禁 JATS 残留、禁 AI 摘要占位符、类型-字段匹配）
由 `check_bib_quality` 自动校验，规则实现见 `tools/check_citation.py`，本文不展开。

> 修改方式：在 Zotero 线上库操作后 `zotero pull` 重新同步（同 §八）。
