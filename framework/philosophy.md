# 设计哲学

> 给**改 PaperGate 本身的人**看：为什么这么分层，什么决定不做。
> 怎么做在代码 docstring 和 `standards/`，这里不重复。
> 只写稳定的判断，不写会随代码漂移的细节。

---

## 一、它解决什么

论文的难点不是写不出来，是**不知道什么时候可以交**，以及**隔一周回来接不上**。

所以「什么算对」写成文件，「不达标」变成 `exit 1`，「现在该干什么」由目录和 tag 判定。
状态在仓库里，不在对话里——对话一关就没了。

---

## 二、人机边界

| 类型 | 归谁 | 为什么 |
|:--|:--|:--|
| 外部不确定性（选刊、文献甄别、审稿回应） | **人** | 涉及主观判断，AI 联网抓这类信息极易引入幻觉 |
| 内部确定性（格式、结构、引用闭合、阶段推进） | **机器**，不打断 | 单一确定路径，投入一次无限复用 |
| 能自动但不可靠（如 PDF 提取保真度） | **人抽查** | 做成检查只会误报，抽查收益不低于全检 |

---

## 三、核心与技能的分界

**核心不在，项目开不了工；技能不在，开得了工，只是少一块能力。**

技能分两档，判据是**核心检查读不读它的产物**：

| 档 | 内容 | 缺失时 |
|:--|:--|:--|
| **必备**（稿件契约的生产者） | 文献管理、导出 | **error**——核心检查无条件读 `references.bib` / 笔记 / 投稿包，没有生产者是一堆修不好的红 |
| **可选**（能力块） | 审查、专题检索 | 「未启用」——装了才有、没装就没有，不产出假的通过 |

必在核心的是骨架，不是能力：项目骨架、目录契约、稿件契约、阶段状态机、检查引擎。
必备技能仍然住在 `skills/`、仍然可替换实现——只是**不允许缺席**。

两条不可破的规则：

1. **技能对核心单向依赖**：只允许 `from skill_api import ...`，禁止反向 import `tools/lib_*`。
   `skill_api` 是唯一兼容承诺面（已导出名字不删、不改签名，只追加）。
2. **技能可拔插靠声明，不靠核心知情**：命令、检查项、阶段子状态都由 `manifest.yaml` 声明，
   核心只知道「有什么」，不知道「谁提供的」。删掉目录 = 卸载该能力。

## 四、三种沉默比报错更危险

检查体系失效，通常不是报错太吵，是**沉默得太像通过**。

| 沉默 | 后果 | 机制 |
|:--|:--|:--|
| 判定不了（缺基准、格式不识别） | 被当成没问题 | `add_unverifiable`：显式「未判定」，与「已核查无问题」分开 |
| 未启用（能力块没装） | 被算进通过数 | `add_skipped`：单列「未启用」，不计通过、不进 errors |
| 装坏的技能（导不进、函数名错、缺字段） | 看起来装好了 | 加载即校验，逐条报错——**没装是明确缺失，装坏是伪装成可用** |

---

## 五、确定性边界与反过度工程化

- **显式声明胜过脆弱推断**：能用「声明式信任模型 + 审查期兜底」解决的，不搞静态扫描类黑魔法；
- **确定性做硬门禁，模糊性给弱提醒**：判不了的降 warning，或交给审查期列底稿；
- **严禁削足适履**：规则是仆人，论文是主人。规则与正文冲突时先判断该改哪边，
  **绝不为了过检查去删内容、降要求**；
- **外部形态归外部**：第三方模板/样式/格式附件用配置表达，表达不了的写一次性后处理，
  不往框架里加分支。判据：这条规则下次会被别的项目用到吗？不会 → 留在项目里。

---

## 六、有意留白的红线

下面这些**不是尚未实现，是决定不做**。代码挡不住「不要建这个」，只有这一节能挡。

| 不做 | 为什么 |
|:--|:--|
| 脚本 AST 静态依赖扫描、启发式代码模式扫描 | 脆弱推断，误报噪音远大于收益 |
| 逐表深度数字溯源 | 只做表存在性闸门 |
| 通用术语全文语义统一 | 超出确定性边界 → 审查期底稿 |
| 期刊名自动推导 CSL | 无条件可靠映射 → 作者投稿前核对 |
| 图表文件自动重命名 | 涉文件 / 引用 / 脚本三处联动 → 人确认 |
| 导出产物完整性的独立检查 | 同一判据不做两遍，导出工序已阻断 |
| 通用依赖清单 / 依赖图 | 维护清单本身就是脆弱推断，只查已知硬依赖 |
| 声明件检查项穷举（资助 / AI 使用 / 独创性…） | 各处要求不同，穷举必过时 → 只提醒一次 |
| 技能路径沙箱 | 技能以当前用户权限运行，半吊子沙箱不如讲清「只装可信来源」 |

新增或清退检查项前的五问，见 [`ARCHITECTURE.md`](../ARCHITECTURE.md#新增或清退一个检查项前先过五问)。
