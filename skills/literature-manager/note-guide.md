# Literature Manager — 文献笔记规范与精修提取指南

> 适用范围：文献笔记的标准定义、多模态 PDF 提取排版与结构化**生成、定点读取**。
> 执行者：当前对话直接执行；或新开对话读取本指南执行。

---

## 〇、 证据决策树（何时需要补笔记）

当写作或审计中发现某篇被引文献**缺笔记**时，按以下决策树判断，**不是一律补笔记**：

```
被引文献缺笔记
  │
  ├─ 摘要够支撑正文引用？──是──→ 不转 PDF、不做笔记（直接引用 bib abstract，证据等级 partial）
  │
  └─ 摘要不够（需正文细节/实证数据）？
      │
      ├─ 能找到 PDF？──是──→ 转 PDF → full_text 笔记（场景 A，generated_by: pdf_extract）
      │
      └─ 找不到 PDF？
          │
          ├─ 有摘要？──是──→ AI 联网补充背景 + 结合摘要 → concept_note（场景 B，generated_by: ai_summary）
          │
          └─ 无摘要？───→ AI 联网搜索权威元数据 → concept_note（场景 B，generated_by: ai_summary）
```

## 一、 文献笔记的标准格式

每篇笔记保存在 `references/notes/{citekey}.md`（扁平目录，禁止子目录），由 **Frontmatter** 与 **Markdown 正文** 组成。

### 1.1 Frontmatter 模板（严格格式强制）

```yaml
---
title: "论文标题"                     # 必填，双引号包裹
source: "作者 (年份). 标题. 期刊, 卷, 页."  # 必填，人可读引用文本
citekey: "<author>_<word>_<year>"    # 必填，与 bib/paper.md/文件名完全一致
doi: "10.xxxx/xxxxx"                 # 可选
note_type: "full_text"               # 必填: full_text | concept_note
generated_by: "pdf_extract"          # 必填: pdf_extract | ai_summary
source_words: 12345                  # full_text 必填: 原始提取词数（CJK 逐字 + 英文单词口径）
generated_at: "2026-08-29"           # 可选，生成/修订日期
lang: "en"                           # 可选: en | zh（原始文献语言，缺省按论文主语言）
---
```

**格式与字段规则**：
- **`note_type` 与 `generated_by` 强绑定**：
  - `note_type: "full_text"` 必须对应 `generated_by: "pdf_extract"`；
  - `note_type: "concept_note"` 必须对应 `generated_by: "ai_summary"`。
- **纯通用字段原则**：Frontmatter 严禁添加 `abstract`、`keywords` 等非通用字段。摘要一律放正文 `## Abstract` 段落。
- **引号风格**：字符串字段一律用双引号，数字字段（如 `source_words`）不加引号。
- **`source_words`**：**词数基准**（CJK 逐字 + 英文单词口径），供 `note_word_preservation` 用。
  由 `lit refresh-words` 按现行口径维护——**计数口径变过就重跑一次**，别把基准留在旧口径上
  （分母偏小会让比值虚高，检查项随之失效；越过正常上界时由 `note_word_preservation` 报出并提示重跑）。
  ⚠ 它**只拦「整篇被摘要式提取」**，不证明提得全、提得对不对。

## 二、 场景 A：多模态 PDF 转 full_text 笔记

> 提取管线的**步骤、命令与「直读 PDF 规范」见 `SKILL.md` §二**，此处不重复。
> 本节只管**产出长什么样**，以及**产出后怎么自检**（§2.3）。

### 2.1 成品笔记清洗规范

> ⚠ **精修不是改写。** 允许做的只有三件：**删**非正文（页眉页脚等）、**定**标题层级、**转**表格与公式。
> **正文文字一字不改**——疑似笔误、口语化表述、术语前后不一致，**一律照录**，在报告里记一笔即可。
> **不得做同义替换**：改词、改数、改表号图号、改作者名年份，都属**事故**，不是润色。

#### ✅ 必须保留的内容：

- Abstract（完整保留，放在 `## Abstract`）；
- 全部正文章节（Introduction → Conclusion，**用 Markdown 标题标出层级**）；
- 公式（行内 `\(...\)`，独立块 `\[...\]`）；**原刊带号的公式要带号**（`\tag{n}`）——否则正文里
  「式 (3-4)」这类引用会悬空；
- **表格（转为标准 Markdown 表格）**。`<!-- Table N: 题注 -->` 写在表体上方、**兼作题注**；
  文字层确实取不出的（扫描件、复杂跨页表）可只留题注，**但须把该表的关键数值写进题注本身**；
- 图占位与说明（`<!-- Figure N: caption -->`），**放在引用它的那一小节**，随论述不随印刷顺序；
- 参考文献列表（`## References` 完整保留）；
- **正文里的括号式文内引注**（`(作者, 年)`）——原样留在原位，**不得整批删去**（它是回溯出处的唯一线索）；
- **关键实证数据**：被正文引用的相关系数、回归系数、样本量等数字必须完整保留进笔记。

> 论文标题与作者行（正文开头 `# Title` + `**Authors**`）**可省**——与 frontmatter `title` 重复。
> run-in 斜体小标题（段首紧接正文）**保留为段内 lead-in，不提升为标题**，否则其后段落会被错误归属。

#### ❌ 必须剔除的内容：

- **页眉页脚**：期刊名、卷期号、印刷页码、DOI 行、出版商网址；
- **编辑与作者信息块**：EDITED BY、REVIEWED BY、CORRESPONDENCE（邮箱）、机构地址、脚注标记；
- **版权声明**：COPYRIGHT、CC BY 许可文本、"This is an open access article..."；
- **下载水印**：JSTOR/ResearchGate 水印；
- **基金致谢**：Funding、Acknowledgments；
- **一切形式的分页标记**：`<!-- Page N -->` 注释、段尾原刊页码括注等。

#### 层级怎么定

**每一篇论文都有层级，只是有时没有编号。** 按序用三种办法，不要平铺成一堆同级标题：

| 情形 | 怎么定 |
|:--|:--|
| **原刊有编号**（`2.`／`2.1.`）| 照编号，`##` 对一级、`###` 对二级，**编号写进标题文本**（否则 `--at "2.4"` 定位不到）|
| **无编号**（原刊用光标题，靠字号加粗分级）| 按**语义嵌套**——哪个标题统辖哪些 |
| **语义也拿不准** | **直读该页 PDF**：字号与加粗在文本层里已经丢了，排版层级只能看图 |

#### 提到哪一层为止（**默认到原刊三级**）

**默认标到原刊三级标题**（`##` 一级 / `###` 二级 / `####` 三级）。再往下**只在该节有独立可引内容时才立节**——
独立实证结论、独立方法说明、独立测量工具；否则并入上级节正文，**保留其文字**。

| 判据 | |
|:--|:--|
| **立节** | 该节**有子节**，**或**其自身散文 **≥ 40 词**（与 §2.2 的摘要判据同源）|
| **不立节** | 无子节、自身散文又不足 40 词——多是一句过渡或引出一张表 |

> 判据看**内容**不看**级别**——按级别一刀切会「该砍的没砍、不该砍的砍了」。

#### ⚠ 分项标题也是标题（**`（1）`／`(1)` 一族**）

中文期刊论文与部分英文论文，子标题**不用编号体系，而用 `（1）（2）（3）` 或 `(1)(2)(3)` 开头**，
独立成段、后续接正文。**这类必须标成 `####`（或相应层级），不能当普通段落留在正文里**——
漏标会把子节正文归进上级节的自身正文，摘要与选节都会错位。

**唯一的判据是：末尾有无句末标点。** 标题是名词短语、**不带 `。．.，：；`**；
编号列表项与算法步骤是完整句子、**带句末标点**。

> 漏标由 `check` 的 **`note_heading_gaps`** 项检出（判据与误报边界见 §2.3）。

> **第三类：提取时新写**——**节摘要行**（上面几表管「原文有什么、留什么」，它不属于这两者），见 §2.2。

### 2.2 节摘要行（**提取时新增**，`full_text` 笔记必做）

**目的**：让**目录树自己说话**——不打开全文就知道每一节大体讲什么。
`note-sec --list` 会把它并到标题后面一起显示。

#### 格式（严格）

**每个"该有摘要的节"**，紧跟着写一行摘要，然后才是正文。**判据只有一条**：

> **≥H2　且　本节自身正文 ≥ 40 词　且　标题不在豁免表内**
> —— 由 `lib_common.needs_gist()` 判定，渲染（`--list`）与校验（`check`）**共用同一个函数**。

（"本节自身正文"＝不含子节、**不含表格行与图表占位**的散文部分。整节是表的节——缩略语表、图表索引、题量清单——**不该有摘要**。口径见 `lib_common.strip_non_prose()`，与论文侧同一份实现。）

| 规则 | |
|:--|:--|
| **标记** | 行首固定 `> 本节：`（**全角冒号**），写在标题下**空一行**处 |
| **语言** | **一律中文**，与文献原文语言无关（与既有 `keywords` 的惯例一致） |
| **长度** | **≤40 字**（口径同 `lib_common.count_words`：对齐 Word 字数统计，汉字与中文标点逐字计）。超长的由 `--list` 回执点名 |

#### 写哪一类，**由节类型决定**（不是自由三选一）

**先认节类型，再落笔**——这样多篇之间才不会漂。

| 节类型（按标题认）| 写哪一类 |
|:--|:--|
| 引言／背景／文献综述 | **做了什么**——铺什么论证（对象＋脉络）|
| 理论／假设／模型 | **做了什么**——提出了什么命题 |
| 方法／材料／数据／测量／样本 | **做了什么**——对象＋方法＋样本量 |
| **结果／发现／实证** | **得到什么**——**必须带数** |
| 讨论／结论 | **得到什么**——结论，**不重复**结果节的数字 |
| 局限／展望／未来研究 | **做了什么**——主张什么 |
| 管理／实践启示 | **做了什么**——提什么建议 |
| 附录／推导／参数 | **怎么组织的** |

**没有对应节类型的**（综合性小标题、栏目式小节）：按「**怎么组织的**」写。

#### 三条禁令

| 禁 | 词表 |
|:--|:--|
| **禁重复「本节」** | 前缀已含「本节：」，正文直接写动词或名词短语，不再出现「本节」二字 |
| **禁评价** | 系统梳理／重要发现／值得关注／具有重要意义／意义重大／深入分析／值得注意／系统阐述 |
| **禁跨文献** | 本文／本论文／本章／提供了依据／与第 X 章／见第 X 章 |

写的是「**这一节本身讲了什么**」（文献侧属性），不是「论文哪一章用了它」（论文侧属性，会静默过时）。

#### 范围与例外

| 情况 | 处理 |
|:--|:--|
| **豁免标题** | `Abstract`／`摘要`／`References`／`参考文献`／`Notes`／致谢类 |
| **自身正文 < 40 词** | 不写。纯结构性父节（无自身正文、直接是子标题）自动落在这一条 |
| **`concept_note`** | 不适用——本身只有几百字，直接读全文 |
| **尚未补上的笔记** | 由 `check` 的 **`note_gist`** 覆盖率反映；**用到哪篇补哪篇** |

严重度 info。**写完当场自检**——命令与回执判读见 `SKILL.md` §二 第 4 步（只在那里写一遍）。

### 2.3 提取自检

> **为什么要分类**：判据的确定性不一样。**做成 `check` 还是做成工序，就按这个分**——
> 框架 `check` **一律不读 `tmp/`**（那里是临时区），故凡**依赖文字层**的校验，都只能在提取那一步做。

#### 甲、框架 `check`（不依赖 `tmp/`，随时可跑）

| 检查项 | 判据 | 误报纪律 |
|:--|:--|:--|
| `note_gist` | 节摘要覆盖率；判据由 `lib_common.needs_gist()` 唯一回答 | 报的是**计数**，不是缺陷数——一行看清进度 |
| `note_heading_gaps` | `lib_common.find_unmarked_headings()`：独立成段 ＋ 末尾无句末标点 ＋ **后接成段散文** ＋ 不在标题树 | ⚠ 只答「**疑似漏标**」，**不答该标几级**——层级回 PDF 按编号／字号判断 |
| `note_table_gaps` | 题注之后无表体。题注认两种写法：**注释式**与**整行被强调符包住**式 | ⚠⚠ **条数不等于缺陷数**：按约定「题注承载关键数值、表体留白」的也在内。**只有文字层本有表体而笔记没转的，才是缺陷**。<br>⚠ **裸写的 `Table N. …` 不认**——正文句也这样起头，认了每 4 条上报有 3 条是正文句（误报率 75%）。**这一族是已知盲区**，靠人工看 |
| `note_word_preservation` | 正文词数 / `source_words` | ⚠ **只拦「整篇被摘要式提取」**，不证明提得全。分母是**声明值**，口径变过即不可比——比值越过正常上界（实测重算后最高 1.24，阈值取 1.35）时报「**分母疑为旧口径**」并提示跑 `lit refresh-words --apply` |
| `note_structure`／`notes_frontmatter`／`notes_flatness`／`notes_bib_closure` | 层级连续性、字段、扁平目录、与 bib 闭包 | 判据确定，报出即可直接改 |

#### 乙、提取当步的机械自检（依赖文字层，**在提取那一步做完**）

| 自检 | 判据 | 已知误报与排除法 |
|:--|:--|:--|
| **逐句命中** | 笔记散文按句拆开，**去掉全部空白后**须是文字层子串 | **六项归一缺一不可**：① 断句含中文句末标点，且 ASCII 的 `.?!` 后须有空格；② 中文标点字形归一；③ 剥 Markdown 标记；④ 字形替换 `¼`→`=`、`þ`→`+`（**须在 NFKC 之前做**）；⑤ 全角→半角 NFKC；⑥ 折叠连续连字符 |
| **字符级对齐** | 逐段做字符级 diff，看文字层最相近区段的增删改 | **唯一能抓「词级改写」的一层**——整句命中率对它不敏感，专名与单复数最易被这样改掉 |
| **引注保留率** | 文字层正文的 `(作者, 年)` 逐个回笔记找 | ① 切参考文献须按**裸行** `References` 切（文字层没有 Markdown 标题），否则整张参考表的年份被算成引注；② 锚定前先剔掉句中插的页眉／下载 URL 器物 |
| **数值闭包** | 笔记散文里每个数值须在文字层查得到 | **唯一能机械抓「改数」的判据**。文字层可能把 `.` 编成 `0`、`,` 编成 `1`，须按编码形再试一遍；**反过来笔记的数比原件「更完整」也是信号** |
| **反向反查** | 文字层 → 笔记，找整段／整列／整节**漏收** | ⚠ **只能逐篇人工做**——按段、按滑窗两版自动化都试败（在「该剔的」与「真丢的」之间划不出线）|

#### 丙、只能人工的三件

| | 为什么做不成检查 |
|:--|:--|
| **通读找指纹**（凭空补写） | 多写的句子在「笔记→文字层」方向上**没有痕迹**——逐句校验是拿笔记去核文字层，笔记多写的压根不会被计为未命中。唯一信号是**指纹不一致**：自造词、体例突变、某词只在一段出现、语气突然变成总结式 |
| **层级定级** | 字号与加粗在文字层里已经丢了，只能看图 |
| **抽查** | 对照 PDF 翻几页，核**章节结构是否完整、关键数字是否对得上、图表有没有漏**；本就无须逐行做，抽查收益不低于全检 |

#### 误报纪律（三条）

1. **阈值用实测定，不用感觉。** 定线前先在全库跑一遍取分布，用**中位数**定，再看误报率能不能接受——
   据感觉定的线一上线就刷屏。
2. **报出后先分类，再动手。** 未命中句逐条归入「原件插了页面器物／字形编码／Markdown 标记／真差异」——
   **看比率下判词一定会判错**：低分的可能一处真差异都没有，高分的可能整段是改写。
3. **文字层本身不比笔记可靠。** 它会把标点编成数字、把重音字母拆成拼接字符、把跨行连字符丢掉或留下、
   把单字母变量写错。**「对不上」只说明需要人看，不说明笔记错了**——判方向要换第二个抽取器交叉验证。

## 三、 场景 B：concept_note 笔记生成（无 PDF）

当文献被引用、无 PDF 且摘要不足以支撑引用时触发。

1. **允许联网**：允许检索期刊官网、Google Scholar 等公开权威元数据补充背景；
2. **严禁无源虚构**：所有内容必须严格可追溯到公开事实，严禁脱离外部输入依赖大模型幻觉编造；
3. **结构精炼**：内容通常几百字，包含核心贡献、关键发现、关键概念，审计时直接读全文。

```markdown
# {Title}

**{Authors}**

## 核心贡献
{文献定位与理论贡献}

## 关键发现
{具体结论与可得的数值点}
```

> ⚠ **只写这两节，不要再加「对本文的用途」一类的字段。**
> 那类字段写的是「论文哪一章用了它」——**论文侧的属性**，会随论文演进而**静默过时**，且没有机制提醒。
> **「哪一章用了哪篇」一律以论文侧为准**，笔记里不复制。

## 四、 笔记使用与定点读取（note-sec）

严禁使用 grep 全文匹配章节标题（可能误命中 frontmatter 内文本）。一律使用框架内置的 `note-sec` 工具：

```bash
python3 ../papergate/papergate.py note-sec references/notes/<citekey>.md --list        # 标题树 + 节摘要（§2.2）
python3 ../papergate/papergate.py note-sec references/notes/<citekey>.md --list --no-gist   # 只看标题树
python3 ../papergate/papergate.py note-sec references/notes/<citekey>.md --at "2.1"    # 定点读取小节
python3 ../papergate/papergate.py note-sec references/notes/<citekey>.md --abstract    # 读取正文摘要
python3 ../papergate/papergate.py note-sec references/notes/<citekey>.md --search X    # 关键词定位
```

**`--list` 是带摘要的目录树**：选节时**先看它**，不必先读摘要或猜标题。
⚠ **摘要只用于选节，不用于判定**——**判定仍须回原文**（`--at`）：
摘要是导航，不是证据。
